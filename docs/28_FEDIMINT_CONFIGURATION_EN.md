# Fedimint Configuration in LightningOS

LightningOS separates Fedimint into two independent apps:

- **Fedimint Guardian**: runs `fedimintd` and participates in the federation as a guardian.
- **Fedimint Lightning Gateway**: runs `gatewayd lnd` and connects the local LND node to one or more federations.

This follows the Fedimint architecture: the Lightning Gateway is not a guardian. It is a separate economic actor that swaps ecash and Lightning payments.

Upstream references:

- Fedimint deploy guide: <https://github.com/fedimint/fedimint/blob/master/docs/deploying.md>
- Guardian Docker compose: <https://github.com/fedimint/fedimint/tree/master/docker/fedimintd>

## Apps

### Fedimint Guardian

Use this app when the user will be a federation guardian.

It only runs `fedimintd`.

It does not use LND.

Main configuration:

```yaml
FM_ENABLE_IROH: "true"
FM_BITCOIN_NETWORK: bitcoin
FM_ESPLORA_URL: https://mempool.space/api
FM_BIND_P2P: 0.0.0.0:8173
FM_BIND_API: 0.0.0.0:8174
FM_BIND_UI: 0.0.0.0:8175
```

### Fedimint Lightning Gateway

Use this app on the server that has LND and will provide Lightning gateway service for a federation.

It only runs `gatewayd lnd`.

Main configuration:

```yaml
FM_GATEWAY_DATA_DIR: /data
FM_GATEWAY_LISTEN_ADDR: 0.0.0.0:8176
FM_GATEWAY_NETWORK: bitcoin
FM_GATEWAY_IROH_LISTEN_ADDR: 0.0.0.0:8177
FM_GATEWAY_BCRYPT_PASSWORD_HASH: <generated by LightningOS>
FM_ESPLORA_URL: https://mempool.space/api
FM_LND_RPC_ADDR: https://host.docker.internal:10009
FM_LND_TLS_CERT: /data/lnd/tls.cert
FM_LND_MACAROON: /data/lnd/data/chain/bitcoin/mainnet/admin.macaroon
```

The gateway mounts `/data/lnd` read-only.

## Esplora

Both apps use:

```text
https://mempool.space/api
```

This avoids requiring local Bitcoin RPC inside the Fedimint integration.

Tradeoff: this is simpler, but less private and less autonomous than using your own bitcoind. If `mempool.space` is unavailable, rate limited, or unstable, Fedimint can be affected.

## Ports

### Guardian

- `8173/tcp`: P2P TLS.
- `8173/udp`: P2P Iroh.
- `8174/udp`: API Iroh.
- `8175/tcp`: Guardian UI.

### Gateway

- `8176/tcp`: Gateway UI/API.
- `8177/udp`: Gateway Iroh.

Port `10010/tcp` is not used by this integration because it belongs to LDK mode. LightningOS uses `gatewayd lnd`.

Do not expose publicly:

- LND gRPC `10009`;
- LND REST `8080`;
- Guardian UI `8175`, except on a trusted network, VPN, or authenticated proxy.

## Iroh and Public IPs

With Iroh enabled, LightningOS does not require a domain or public IP for a basic federation. Iroh attempts direct connectivity and can use NAT traversal mechanisms.

Opening UDP improves reliability, but it should not be treated as an absolute requirement for tests.

For production, still prefer stable networking, backups, and independent operators.

- Data: `/var/lib/lightningos/apps-data/fedimint-guardian/fedimintd`

- Compose: `/var/lib/lightningos/apps/fedimint-gateway/docker-compose.yaml`
- Data: `/var/lib/lightningos/apps-data/fedimint-gateway/gatewayd`
- Admin password: `/var/lib/lightningos/apps-data/fedimint-gateway/gateway-admin.txt`
- Password hash: `/var/lib/lightningos/apps-data/fedimint-gateway/gateway-password-hash.txt`

## Setting Up a 4-Guardian Federation

Example with you and three other app users:

1. Each of the 4 users installs **Fedimint Guardian** on their own server.
2. Each guardian opens the Guardian UI at `http://<LAN_IP>:8175`.
3. Each guardian sets a strong password.
4. Each guardian generates their setup code.
5. All guardians exchange setup codes with each other.
6. Each guardian enters the other 3 setup codes in their UI.
7. The federation runs DKG.
8. After the federation is created, generate the invite code.
9. The LND operator installs **Fedimint Lightning Gateway**.
10. In the Gateway UI at `http://<LAN_IP>:8176`, paste the invite code under "Connect a new Federation".

The gateway operator may also be a guardian, but does not need to be one.

## Solo Test

For a local test:

1. Install **Fedimint Guardian**.
2. Create a 1-guardian federation.
3. Install **Fedimint Lightning Gateway** on the same server.
4. Open `http://<LAN_IP>:8176`.
5. Confirm the gateway status is `Running`.
6. Confirm the Lightning Node section shows:
   - Node Type: `External LND`;
   - Status: `Synced`;
   - Block Height greater than zero.
7. Connect the gateway to the federation using the invite code.

## Uninstall

Uninstall is intentionally destructive for both apps.

When uninstalling **Fedimint Guardian**, LightningOS:

- stops the compose project;
- removes compose containers/orphans/volumes;
- removes `/var/lib/lightningos/apps/fedimint-guardian`;
- removes `/var/lib/lightningos/apps-data/fedimint-guardian`;
- removes the `fedimint/fedimintd:v0.11.1` image.

When uninstalling **Fedimint Lightning Gateway**, LightningOS:

- stops the compose project;
- removes compose containers/orphans/volumes;
- removes `/var/lib/lightningos/apps/fedimint-gateway`;
- removes `/var/lib/lightningos/apps-data/fedimint-gateway`;
- removes the `fedimint/gatewayd:v0.11.1` image;
- does not alter `lnd.conf`.

Before uninstalling a real guardian, download a backup from the Guardian UI. Removing guardian data removes that guardian's local identity and material.

## Migration from the Old Combined App

Older LightningOS versions used one `fedimint` app with `fedimintd` and `gatewayd lnd` together.

When installing the new apps, LightningOS migrates conservatively:

- installing **Fedimint Guardian** moves `/var/lib/lightningos/apps-data/fedimint/fedimintd` to the new Guardian directory;
- installing **Fedimint Lightning Gateway** moves `/var/lib/lightningos/apps-data/fedimint/gatewayd` and the password files to the new Gateway directory;
- if the old compose exists, it is stopped before migration.

If the new directories already exist, automatic migration does not overwrite them.

## Common Issue: LND Fails on an Old Docker IP

Typical error:

```text
listen tcp4 172.19.0.1:10009: bind: cannot assign requested address
```

This means `lnd.conf` contains an old `rpclisten` line pointing to a Docker bridge that no longer exists.

Repair commands:

```bash
sudo cp /data/lnd/lnd.conf /data/lnd/lnd.conf.bak-fedimint-$(date +%Y%m%d-%H%M%S)
sudo sed -i '/^rpclisten=172\.19\.0\.1:10009$/d' /data/lnd/lnd.conf
sudo sed -i '/^tlsextraip=172\.19\.0\.1$/d' /data/lnd/lnd.conf
sudo rm -f /data/lnd/tls.cert /data/lnd/tls.key
sudo systemctl restart lnd
sudo journalctl -u lnd -n 80 --no-pager
```

Do not remove `rpclisten=127.0.0.1:10009`.

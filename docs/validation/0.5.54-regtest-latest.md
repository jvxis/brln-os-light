# Regtest latest-release bootstrap validation

Scope: only the isolated regtest bootstrap/installer and documentation. Production
installers, the UI updater and the mandatory 0.5.40 bridge are unchanged.

## Environment and baseline

- Disposable `los-disposable-0554-regtest-bootstrap`, Ubuntu 24.04.3 amd64,
  4 vCPU, 8 GiB RAM. No production LND, Bitcoin or LOS services/data.
- Baseline: 8 existing regtest bootstrap tests passed; 16 production bootstrap
  tests passed on native Linux.
- New release-selection/fail-closed tests against the old bootstrap failed as
  expected (10 assertions/subtests). The old default selected the development
  branch and did not attest the release.

## Focused regression checks

Native Linux commands:

```sh
bash -n lo_regtest_bootstrap.sh lightningos-light/install_regtest.sh
python3 -m unittest discover -s scripts/tests -p test_regtest_bootstrap.py -q
python3 -m unittest discover -s scripts/tests -p test_install_bootstrap.py -q
python3 -m unittest discover -s scripts/regtest-lab -p 'test_*.py' -q
```

Results: 15 regtest tests, 16 production bootstrap tests and 31 laboratory-helper
tests passed on the committed candidate `1ecd8897`. The helper tests use fixtures;
they do not substitute for the real native installation below. Coverage
includes repeated dispatch/cleanup, explicit development commits, required
disposable acknowledgement, unsafe refs, wrong hostname, non-systemd hosts,
production service rejection, installer failure propagation, immutable published
metadata, API failure without fallback, newer development branches, annotated
tags, source commit mismatch, version mismatch, direct-installer latest default,
explicit checkout mode and prevention of recursive bootstrap dispatch.

The Windows attempt could not run shell integration tests because its `bash`
resolved to an unconfigured WSL launcher. It is not counted as passed; the checks
above were subsequently run successfully on the disposable Linux VM.

## Real installation

Invoked the candidate `install_regtest.sh` with its default source;
it dispatches the candidate bootstrap and installs the real latest immutable
release. Catalog resolution selected `0.5.53-Beta`, source commit
`1d01ad2deef4d40e80a60d4e349d3cc151194485`, rather than development 0.5.54.

The real run installed missing curl prerequisites, verified the immutable source,
prepared Go 1.26.10, built the Go Manager and React UI successfully and provisioned
native Bitcoin/LND units. Bitcoin and Alice/Bob/Charlie LND services were active.

The guest then suffered Linux watchdog **soft lockups** across multiple CPUs
(including sshd, swapper, systemd-resolved and unattended-upgrades). SSH
authentication timed out. Host inventory still showed about 10 GiB free memory
and only this disposable plus protected LOS-TEST2 running. The cause of the guest
lockup is not established; this is not evidence that installation finished.
Normal ACPI shutdown did not complete. The owner subsequently authorized forced
power-off of this exact disposable; VirtualBox confirmed `poweroff`. Disks and
records were preserved, and LOS-TEST2 remained running.

Not completed in this run: full wallet initialization, all three authenticated
panels and native LND/Bitcoin functional checks, and repeated installation/data
preservation checks. Do not count these as passed.

## Owner-approved validation scope (2026-11-07)

The owner explicitly waived repeating the previously exercised laboratory
functional tests and authorized removing the PR from draft. Acceptance for this
change is focused on `install_regtest.sh` and the curl bootstrap selecting the
latest published release, which was verified above. The incomplete full-run
checks remain documented; this waiver does not imply a successful end-to-end
installation or a diagnosed cause for the guest lockup.

ARM and WSL2 native installation are not claimed. This regtest profile only
supports Ubuntu 24.04 amd64; no shared production installer requirements changed.

# Regtest latest-release bootstrap validation

Scope: only the isolated regtest bootstrap/installer and documentation. Production
installers, the UI updater and the mandatory 0.5.40 bridge are unchanged.

## Environment and baseline

- Disposable `los-disposable-0554-regtest-bootstrap`, Ubuntu 24.04.3 amd64,
  4 vCPU, 8 GiB RAM. No production LND, Bitcoin or LOS services/data.
- Baseline: 8 existing regtest bootstrap tests passed; 16 production bootstrap
  tests passed on native Linux.
- New release-selection/fail-closed tests against the old bootstrap failed as
  expected (10 assertions/subtests). The old default selected the development
  branch and did not attest the release.

## Focused regression checks

Native Linux commands:

```sh
bash -n lo_regtest_bootstrap.sh lightningos-light/install_regtest.sh
python3 -m unittest discover -s scripts/tests -p test_regtest_bootstrap.py -q
python3 -m unittest discover -s scripts/tests -p test_install_bootstrap.py -q
```

Results: 15 regtest tests and 16 production bootstrap tests passed. Coverage
includes repeated dispatch/cleanup, explicit development commits, required
disposable acknowledgement, unsafe refs, wrong hostname, non-systemd hosts,
production service rejection, installer failure propagation, immutable published
metadata, API failure without fallback, newer development branches, annotated
tags, source commit mismatch, version mismatch, direct-installer latest default,
explicit checkout mode and prevention of recursive bootstrap dispatch.

The Windows attempt could not run shell integration tests because its `bash`
resolved to an unconfigured WSL launcher. It is not counted as passed; the checks
above were subsequently run successfully on the disposable Linux VM.

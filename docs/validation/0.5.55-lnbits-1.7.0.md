## Image/database upgrade and persistent MFA

The separate `scripts/tests/lnbits-170-upgrade-regtest.py` scenario also passed
on this disposable. It starts the old pinned 1.6.2 image, creates an account,
retains its wallet IDs/balances and a custom admin setting, stops it and replaces
the container with pinned 1.7.0 using the same data. It verifies preserved
account/wallet/balance/settings/auth key and zero installed extensions. This
fixture uses VoidWallet with a zero balance; funded invoice/payment behavior
is covered independently by the native regtest suite above.

The old image persisted 2FA disabled in its settings DB. The upgrade correctly
preserved that value rather than forcing the new environment default over it.
The test then enabled 2FA through the authenticated admin API, enrolled TOTP,
saved recovery acknowledgement, replaced the 1.7.0 container again and verified
the unchanged persistent TOTP key, required login challenge and successful
recovery. The first fixture attempt incorrectly read `balance` from account
wallet objects; these expose `balance_msat`. The assertion was corrected, not
removed. The second attempt incorrectly expected environment defaults to
override existing admin policy; it was corrected to assert policy preservation
and test explicit admin enablement instead.

Server test binary SHA256:
`37159805e875e909f79dda3060e535e298026e627ff5c2ad6baf0465f6634f01`.
Test containers removed after completion; private disposable data retained.

## Remaining coverage boundaries

This is an App Store image/defaults change, not a new production installer or
Manager updater. No full install.sh/install_existing.sh/old-Manager upgrade
matrix was repeated. No native ARM run, mainnet financial test, production
deploy, or exhaustive third-party extension compatibility claim. Existing
extension data is not uninstalled or rewritten by this change. Persistent
database migrations belong to LNbits; retain a private pre-upgrade backup.

# LNbits wallet-only credential validation (0.5.55 candidate)

Status: **draft; not ready to merge**. References issue #394. No production
node was changed. This validates least privilege, not the origin of any reported
incident.

## Changes and boundaries

- New LNbits credentials retain info read, invoices read/write and offchain
  read/write. On-chain and peer authority is removed. Lightning payments remain
  possible and do not inherit LightningOS spending guards.
- Existing exact legacy catalog credentials are migrated with a persisted retry
  record. Only LNbits is stopped/reloaded; TLS files and LND are not changed.
- Revocation is a narrow no-argument broker operation. The Manager gains no
  macaroon-write permission. The broker checks authentication and its private
  enrolled credential before revoking a dedicated non-default root.
- Revocation invalidates **all copies** of that app credential. Sharing an App
  Store credential with another app is unsupported. Unknown/custom credentials
  fail closed and require review rather than automatic replacement.
- Explicit stop/uninstall cancels pending automatic resume. An interrupted
  migration does not restore the previous broader authority.
- English/Portuguese Store and installation-confirmation notices explain that
  LNbits node-management features are unsupported with this wallet credential.
- No firewall changes. Public exposure of port 5000 requires separate review;
  this PR must not be represented as resolving network exposure.

## Baseline and automated tests

Windows amd64, Go 1.26.0 (`GOTOOLCHAIN=local`): existing focused LNbits/registry
baseline passed. The wallet-only permission assertion failed against the old
policy (extra onchain/peers permissions) and passed after reduction.

`go test -p 1 ./...` and `go vet -p 1 ./...` passed after the migration/broker
implementation. Tests cover running/stopped states, malformed/custom/default
credentials, forged signatures, unknown runtime, interrupted stop/delete/bake/
restart, idempotence, operator stop, enrollment mismatch and strict broker request
shape. These use fixtures and do not replace production Docker lifecycle tests.

UI: `npm run build` passed (existing bundle-size warning). The browser test
`ui/tests/lnbits-wallet-notice.browser.test.mjs` passed in headless Edge, English
and Portuguese, desktop and narrow viewport. Store and confirmation notices were
checked, other app notices preserved, and no mutating API requests were sent.

## Native Linux regtest, 2026-11-08

Dedicated `los-disposable-regtest`, Linux amd64, native Bitcoin/LND, fictitious
coins only. Alice/Bob/Charlie were synchronized with two active channels each;
automatic mining was active at 60 seconds. No LND restart or TLS change.

Observed with a dedicated temporary root, removed after every test attempt:

- GetInfo, ChannelBalance, invoice listing and invoice creation succeeded.
- Bob paid Alice; restricted credential retrieved the settled invoice.
- Restricted credential paid Bob through Router SendPaymentV2 successfully.
- On-chain send, channel open/close and peer connect requests using invalid
  targets were rejected by macaroon authorization before execution.
- Revoke/rebake of the same numeric root invalidated the old credential.
- Unrelated root IDs were unchanged after cleanup.

The first harness attempts required corrections: lncli payinvoice emits a stream
rather than a single JSON object; the legacy synchronous REST payment path was
not registered; streamed authorization errors use an error envelope. Final
assertions checked settled invoices, successful Router payments and actual
permission-denied errors, not merely non-200 status.

The actual Go client was also executed on Linux (not just cross-compiled):

```
LOS_REGTEST_MACAROON_TEST=1 ./lndclient.test \
  -test.run TestMacaroonAuthenticationRegtest -test.v
```

PASS: native identifier parsing, CheckMacaroonPermissions, denial of on-chain
authority, revocation, rebake and old-credential rejection. The opt-in test
refuses any host/network other than the fixed disposable regtest fixture.

# 0.5.56-Beta — LND UI upgrade helper digest

## Cause and scope

The 0.5.55 helper added the pinned upstream signer required by LND 0.21.8, but
the broker still allowed the 0.5.54 helper digest. Actual LOS-TEST2 UI start
returned `lnd_upgrade_failed` before a unit/log was created. Validation-only
requests reproduced the rejection; LND remained on 0.21.4 without restarting.

Change only the broker's single reviewed SHA-256 pin:
`bf187e1a029667fe93535ec5059e851a06e725d090f606135d05943e7f1765ba` ->
`7bb3df07386fbad1701d3843a6907de189b20bd960fb80ecb4ed5980d3ea28fa`.
No allowlist broadening, helper change, signature-threshold reduction, caller
URL support, protocol/installer requirement change or bypass of the broker.

## Assisted deployment / remaining gate

Only the corrected broker will be applied to LOS-TEST2, retaining its released
0.5.55 Manager/UI and a root-only broker rollback copy. No automatic LND upgrade,
restart, TLS/config change or financial operation is authorized in this patch
deployment. The owner will repeat the actual upgrade from the UI.

Keep the PR draft until that assisted upgrade is confirmed. Native ARM and full
fresh/install_existing/old-LOS installer matrices were not repeated; requirements
and installers are unchanged. No frontend code changed, so no new UI build is
claimed for this fix. The real broker verification dispatch is not mislabeled as
an end-to-end LND binary replacement/rollback pass. No merge or release requested.

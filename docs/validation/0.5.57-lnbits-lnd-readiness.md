# 0.5.57: LNbits startup waits for LND

Tracks [issue #419](https://github.com/jvxis/brln-os-light/issues/419).

## Cause and scope

LNbits 1.7.1 defaults to four funding-source retries. If LND is still starting
or locked when those attempts finish, LNbits switches to `VoidWallet` without
an automatic switch back in that startup path. The inspected upstream sources
are [`app.py`](https://github.com/lnbits/lnbits/blob/v1.7.1/lnbits/app.py),
[`settings.py`](https://github.com/lnbits/lnbits/blob/v1.7.1/lnbits/settings.py)
and [`lndrest.py`](https://github.com/lnbits/lnbits/blob/v1.7.1/lnbits/wallets/lndrest.py).

The Store's closed Compose command now waits for the authenticated
`GET /v1/balance/channels` used by `LndRestWallet.status()`. A valid zero balance
is ready; graph synchronization or a positive balance is not required. Requests
use a five-second network timeout, retry every five seconds and emit a generic wait
message at most once per minute. The container has not started the LNbits web
server while waiting; the Store's process-running badge alone is not readiness.

The script is compiled into the catalog, snapshotted by the broker and runs
inside the same pinned, non-root, capability-free container on every start,
including Docker's `unless-stopped` autostart. It needs no running Manager to
wait. After readiness it replaces itself with the existing LNbits executable
and arguments. There is no runtime watchdog or automatic payment retry.

## Preserved boundaries and adoption

- Same image digest, wallet-only macaroon, TLS verification, ports and mounts.
- Only read-only status RPCs; no changes to LND, its configuration, TLS keys or
  certificates; no LND restart, new permissions or new package requirements.
- No account, balance, extension, 2FA or database migration is added.
- Probes do not use environment proxies, follow redirects or log endpoints,
  response bodies or credentials. Certificate files are re-read each attempt.
- Existing broker Stop remains independent of installed Compose/image version.
  Remove still preserves application data; those regression suites remain in
  scope even though their implementations are unchanged.
- **Existing installations adopt this command after one Store Stop → Start
  with the updated LOS.** An LOS update alone does not silently recreate a
  running LNbits container. Start reconciles the catalog as before. A container
  manually stopped by the operator must stay stopped.
- An existing `VoidWallet` instance still requires operator Stop → Start.
  No generic VoidWallet watchdog is introduced: upstream security protections
  can deliberately select that funding source. Runtime recovery must not undo
  those protections. This addresses the issue's startup-order proposal, not
  every possible funding-source failure or a race after the initial probe.
- Native/external LNbits installations outside the Store are not modified.

## Validation record

Platform: Windows amd64, Python 3.11, local Go toolchain.

Baseline at `3812f34547b53ddaaea00458c7dad08dd32f0def`:

```text
go test -p 1 ./internal/appmanifest ./internal/privileged ./internal/server \
  -run 'LNbits|Lnbits|ValidateAppRegistry' -count=1
PASS
```

The new startup-contract regression failed on the original implementation,
which executes LNbits directly. It passes with the embedded gate. Tests also
parse the generated Compose YAML to verify that Docker receives the unchanged
script, and reject a declaration that replaces the gate's TLS verification.

Functional checks include:

- Eight Python behavior tests: zero/nonzero balance, malformed/oversized
  responses, bounded reads/timeouts, invalid endpoints, certificate rejection,
  retries beyond upstream's budget, rate-limited secret-free logs, fixed exec
  arguments, rejected empty/oversized credentials and interruption without
  starting LNbits.
- Real Python HTTPS requests to local synthetic TLS fixtures: authenticated
  zero-balance success, 401/503, refused connection, invalid certificate,
  certificate-file refresh, wrong macaroon, ignored proxy variables and a
  redirect whose target receives no request. No real wallet or funds involved.
- Existing credential migration/revocation, certificate rotation, catalog
  inspection, version-independent Stop, removal/data-preservation and App Store
  registry regression tests.

Commands after the fix:

```text
go test -p 1 ./...
go vet -p 1 ./...
```

Both commands passed. No frontend code or UI/API contract changed.

The first broad test attempt exposed a Windows Python alias rather than an
installed interpreter; the test runner now verifies Python 3 before selecting
it. This was fixed, not skipped. Python-dependent tests explicitly skip if no
Python 3 interpreter is available; such a skip is not functional validation.

## Remaining validation — keep the PR in draft

No Linux VM, node or Docker service was changed during these local tests.
Permission to reuse `los-disposable-0555-lndg` for isolated regtest validation
has been requested. Before marking ready:

1. Reproduce the original behavior with the pinned 1.7.1 image and delayed or
   locked regtest LND; observe the startup fallback, then LND becoming ready.
2. Apply the closed candidate through the real broker/Compose path. Confirm
   it waits beyond the old retry budget, starts with LND ready and successfully
   creates/receives/pays a regtest invoice using the existing narrow macaroon.
3. Exercise actual Docker boot/autostart with delayed LND, UI/broker Stop while
   waiting, stopped-container persistence, repeated starts, and Stop → Start
   adoption from the previous declaration. Preserve accounts, balances, custom
   settings and credentials; verify native TLS/config hashes remain unchanged.
4. Confirm an upstream safety-triggered VoidWallet is not automatically reset.
   Test cancellation and an unavailable/locked LND without affecting another app.

Linux/amd64 Docker/boot integration and native arm64 execution have not been
validated in this record. Windows tests and source inspection do not replace
them. No installer, updater, UI contract or dependency version is changed.

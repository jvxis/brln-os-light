# 0.5.58: LNbits superuser backup validation

Refs #427. Base: `0a218898` (`agent/0.5.58-release`). Date: 2026-11-15.

## Scope and implementation

The pinned official LNbits 1.7.1 image writes its superuser backup ZIP relative
to cwd. The existing read-only `/app` cwd therefore prevents the download.
Simply moving cwd also breaks upstream's relative `lnbits/static` lookup.

The catalog now uses private `/run/lnbits` tmpfs as cwd, with mode 0700,
UID/GID 65532, noexec/nosuid/nodev and a limit of 25% of host physical RAM.
The one-shot startup gate aliases only `/app/lnbits` into that workspace before
waiting for LND. The package itself remains immutable; the ZIP stays outside
the archived `/app/data` and outside the public static root. Incorrect cwd or
an unexpected existing alias fails closed. No upstream monkey patch/image
fork, broker authority, TLS change, new API or process-wide umask is introduced.

The image digest, default extension policy, 2FA settings, env/data mounts,
wallet-only macaroon and LND readiness checks are unchanged. Existing apps
adopt the declaration using Store Stop -> Start after the LOS upgrade; no
automatic recreation of an in-use app. Installers, upgrade helper, dependency
versions and frontend source are unchanged.

## Limits and operator guidance

- ARM was not exercised; do not describe it as passed. The image pin remains
  the existing multi-architecture digest; no installer or toolchain path changed.
- This validates default SQLite backup downloads, not restore consistency of
  every database or arbitrary extension. It does not redesign upstream's live
  SQLite snapshot/concurrent-backup behavior.
- The actual pinned amd64 image has `pg_dump`. Do not repeat the report's
  blanket assumption that it is absent. External PostgreSQL backup/restore
  combinations were not tested here.
- tmpfs may use host swap, and allocation competes with other host memory.
  The private last ZIP remains until overwrite or container stop/recreation.
  No encryption, guaranteed memory-only secrecy or unlimited backup size is
  promised. Backups larger than the memory budget need an operator-managed
  private backup strategy. Never request/post wallet backup contents.
- No full LOS installer/updater matrix or cold VM boot was repeated: those
  components are unchanged. Fresh app creation, prior app declaration adoption
  and Docker restart-policy behavior were tested separately as described.

No merge or release was performed as part of this fix.
